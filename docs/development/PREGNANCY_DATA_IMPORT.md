# Импорт данных о беременности

Этот документ описывает процесс импорта данных о беременности из markdown файла в базу данных.

## Обзор

Система импорта данных состоит из трех основных компонентов:

1. **PregnancyDataParser** (`src/database/utils/pregnancy-data-parser.ts`) - парсер markdown файла
2. **PregnancyDataImporterService** (`src/database/services/pregnancy-data-importer.service.ts`) - сервис для импорта и обновления данных
3. **CLI скрипт** (`scripts/import-pregnancy-data.ts`) - скрипт для запуска импорта

## Использование

### Базовое использование

Импорт данных из файла по умолчанию (`docs/pregnancy-data-by-days.md`):

```bash
npm run import:pregnancy-data
```

### Импорт из другого файла

```bash
npm run import:pregnancy-data -- --file=path/to/file.md
```

### Импорт без обновления существующих записей

По умолчанию существующие записи обновляются. Чтобы только добавлять новые:

```bash
npm run import:pregnancy-data -- --update=false
```

### Просмотр статистики

Просмотр статистики данных в БД:

```bash
npm run import:pregnancy-data -- --stats
```

## Формат данных

Markdown файл должен содержать данные в следующем формате:

```markdown
#### День 1
- **day**: 1
- **week**: 1
- **trimester**: 1
- **babySize**: 0.1-0.2 мм (как крупинка соли)
- **babyWeight**: менее 0.001 г
- **babyDevelopment**: Оплодотворение яйцеклетки сперматозоидом...
- **motherChanges**: Обычно еще нет признаков беременности...
- **tips**: 
  - Начните принимать фолиевую кислоту
  - Избегайте алкоголя, курения
  - Ведите здоровый образ жизни
```

## Валидация данных

Перед импортом данные проходят валидацию:

- Проверка количества дней (должно быть 280)
- Проверка уникальности дней
- Проверка диапазонов (день: 1-280, неделя: 1-40, триместр: 1-3)
- Проверка наличия всех обязательных полей

## Процесс импорта

1. **Парсинг файла** - извлечение данных из markdown
2. **Валидация** - проверка корректности данных
3. **Импорт/Обновление** - сохранение данных в БД
   - Если запись существует и `updateExisting=true` - обновляется
   - Если запись не существует - создается новая

## Логирование

Скрипт выводит подробную информацию о процессе:

- Количество распарсенных дней
- Результаты валидации
- Количество импортированных/обновленных записей
- Ошибки (если есть)

## Использование в коде

Сервис можно использовать программно:

```typescript
import { PregnancyDataImporterService } from './database/services/pregnancy-data-importer.service';

// В вашем сервисе
constructor(
  private importerService: PregnancyDataImporterService,
) {}

async importData() {
  const result = await this.importerService.importFromFile(
    'docs/pregnancy-data-by-days.md',
    true, // обновлять существующие
  );
  
  console.log(`Импортировано: ${result.imported}`);
  console.log(`Обновлено: ${result.updated}`);
  console.log(`Ошибок: ${result.errors}`);
}
```

## Проверка необходимости обновления

Сервис может проверить, нужно ли обновлять данные:

```typescript
const needsUpdate = await importerService.needsUpdate(filePath);
if (needsUpdate) {
  await importerService.importFromFile(filePath);
}
```

## Статистика

Получение статистики по данным в БД:

```typescript
const stats = await importerService.getStatistics();
console.log(`Всего дней: ${stats.totalDays}`);
console.log(`По триместрам:`, stats.daysByTrimester);
console.log(`По неделям:`, stats.daysByWeek);
```

## Обработка ошибок

Все ошибки логируются и возвращаются в результате импорта:

- Ошибки парсинга - выбрасываются исключения
- Ошибки валидации - возвращаются в массиве ошибок
- Ошибки БД - логируются и учитываются в счетчике ошибок

## Рекомендации

1. **Резервное копирование** - перед массовым обновлением сделайте бэкап БД
2. **Тестирование** - сначала протестируйте на небольшом наборе данных
3. **Валидация** - всегда проверяйте валидность данных перед импортом
4. **Мониторинг** - следите за логами во время импорта
